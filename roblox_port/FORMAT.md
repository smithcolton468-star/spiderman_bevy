# SpiderManData pack format

`SpiderManData.rbxmx` is one Folder of ModuleScripts. Insert it with **Insert from File** (ReplicatedStorage is a good
place). It is generated by `tools/build_roblox_pack.py` from the repository's own `assets/`, so rebuild it rather than
editing it.

```
SpiderManData
├─ PackInfo          JSON {compression = "zstd" | "none", format = 1, studs_per_metre}
├─ Decoder           Luau module that reads everything below (luau/Decoder.luau)
├─ Skeleton          JSON {armature_root, joints = [{name, parent, t, r, s, inverse_bind}]}
├─ Clips/<clip name>/001, 002, ...     one payload per animation clip (68)
├─ Collision/Index   JSON {units, assets = {glTF path → [{primitive, model, kit_part}]}, models = {id → counts}}
├─ Collision/Models/<id>/001, ...      one payload per distinct collision mesh (73)
├─ Layout            assets/world/layout.json, as text
├─ Conversion        assets/character/conversion.json, as text
├─ Tuning/<name>     every JSON under assets/tuning (subfolders joined with "__", e.g. native__hero_swing_config)
├─ OracleFixtures/<scenario>/Scenario   tools/native_oracle/scenarios/<scenario>.txt (the inputs)
│                            /Game       crates/sm_traversal/tests/fixtures/<scenario>.json (the game's own path)
│                            /Check      JSON {position_tolerance_m, facing_tolerance_deg, same_mode_every_frame}
└─ ReferencePoses/NN_<name>             JSON {layers = [[clip, time, weight]], joints = [[x, y, z, qx, qy, qz, qw]]}
```

A text module returns its text: `require(module)` gives the string and `Decoder.json(module)` decodes it.

## Payloads

A payload is binary data, compressed with Zstd (level 19, content size in the frame header) unless PackInfo says
`"none"`, then base64-encoded and cut into ModuleScripts of 196,000 characters (`return "<base64>"`). Each part is a
whole number of base64 quads, so each one decodes on its own. Roblox caps a script's Source at 200,000 characters, so
nothing larger can be packed. `Decoder.payload(folder, compression)` joins the parts in name order through
`EncodingService:Base64Decode` and `EncodingService:DecompressBuffer(…, Enum.CompressionAlgorithm.Zstd)`.

All numbers are little-endian.

### Clip (`SMC1`)

| Field | Type |
|---|---|
| magic | `"SMC1"` |
| name length, name | u16, bytes |
| duration (s) | f32: the last key time of any channel, as Bevy computes a clip's duration |
| joint count | u16 (212, in Skeleton order = the glTF skin's joint order) |
| time set count | u16 |
| each time set | u32 n, then n × f32 key times |
| channel count | u32 = joints × 3 |
| each channel header (7 bytes) | u8 flags, u16 time set, u32 keys stored |
| value word count | u32 |
| value words | four byte planes: byte k of every word, then byte k + 1 … |

Channels are in joint order, then path order translation, rotation, scale. Flags: bits 0–1 are the interpolation
(0 LINEAR, 1 STEP), bit 2 means the channel exists, and bit 3 means it is constant (every key bit-identical, so
one key is stored). The words are f32 bit patterns. A constant channel stores its one key's components. A keyed
channel stores each component as a run of differences between consecutive bit patterns (mod 2³²), the first being
the pattern itself. Every value round-trips bit for bit: the build checks all 43,248 channels against the glTF.

`Decoder.parseClip` returns `{name, duration, joints, channels[joint] = {T, R, S}, values}`. Each channel is
`{interp, times, keys, constant, width, offset}`, and its keys are key-major f32 in `values` from byte `offset`.
Rotations are quaternions x, y, z, w.

### Collision mesh (`SMM1`)

`"SMM1"`, u32 vertex count, vertex count × 3 f32 positions (metres, the mesh's own space), u32 index count,
that many u32 indices (three per triangle, in the glTF's order). One model is one glTF primitive, which is one Bevy
`Mesh`, the unit `world::Model` is built from. Identical primitives share one model; the Index lists every asset's
primitives in order. The glTF nodes in these files carry no transform, so an object's transform is the layout's
(position, yaw about +Y, uniform scale).

## Import files

`import/*.glb` are in **studs** (× 1/0.28). Import them with the Scale Unit left at Studs. Everything in the pack is in
metres, like the simulation.

- `SpiderMan.glb`: the 18 suit meshes, with the three over 20,000 triangles each cut in two (`SuitPart_00_a/_b`,
  `01_a/_b`, `08_a/_b`), giving 21 MeshParts. The skin is the same 212 joints with the same names, rest transforms and
  inverse bind matrices, scaled. There are no animations.
- `CityTowers.glb`, `CityProps.glb`: one top-level node per source model (`tower_1`, `sedan_blue`, …). Its children
  are the model's primitives (`<model>_pNN`, with `_a`/`_b` where a tower primitive was split). Each model sits at its
  own origin, as the layout expects.

The materials are baked for Roblox's importer. Each has a colour map with the base colour factor multiplied in (in
linear space, as glTF and Bevy do), the normal map as it was (Bevy ignores `normalTexture.scale`, so this does too),
and a constant metallic-roughness map holding the material's factors (8-bit). Alpha mode, cutoff and double-sidedness
are kept. `manifest.json` lists every material's original factors.

Triangles, normals, UVs, joints and weights are the original ones. The only change is float32 rounding after the
stud scaling, under 0.004 mm.
