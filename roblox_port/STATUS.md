## The one thing that mattered: f32

The Rust computes in 32-bit floats; Luau numbers are 64-bit. A straight port drifts a few millimetres over a swing
(the Rust's f32 positions, computed as `pivot - offset` near 80 m, carry about 1e-5 m of rounding a frame) and fails 3
of the 11 checks by a hair (`basic_jump`, `turn_left`, `hold_auto`). So `tools/build.py` rewrites the traversal
folder with `tools/f32ify` (a small C++ program over Luau's own parser): every arithmetic result is rounded to f32
(`vector.create(x, 0, 0).x`), decimal literals become their f32 values, and functions named `f64_*` are left alone
where the Rust itself uses f64 (the game clock `time` / `entry_time`, part of `spring`). With that, the Luau matches
the Rust to the micrometre.

- `src/` is the readable source (edit this). `build/` is generated by `python roblox_port/tools/build.py --f32ify
  <path>` (or `--luau-src <luau checkout>` to compile f32ify): `build/` is what runs.
- Requires are by string (`require("./Math")`), mirroring the folders.

## Running the CLI tests

The tests read the pack from files: `python roblox_port/tools/extract_pack.py roblox_port/SpiderManData.rbxmx <dir>`
(needs `lxml` and `zstandard`). They need a Luau CLI with `readfile`: Luau `9d7748a` with
`tools/luau_cli_readfile.patch` applied to `CLI/src/Repl.cpp`. Then, from `build/tests`:
`luau oracle_paths.luau -a <dir>`. In Studio the same code reads the pack through `Decoder` instead.
